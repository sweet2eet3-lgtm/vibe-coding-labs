## 1. Описание задачи

### 1.1. Цель работы

Цель лабораторной работы — разработать работающего Telegram-бота с использованием большой языковой модели (LLM), освоить основы вайб-кодинга, научиться формулировать технические требования к программному продукту и тестировать сгенерированный код.

В качестве проекта я выбрал разработку **Feedback Assistant** — Telegram-бота для автоматизированного сбора обратной связи о качестве обслуживания клиентов.

### 1.2. Какую проблему решает бот

Для бизнеса важно регулярно получать обратную связь от клиентов, чтобы оценивать качество обслуживания и своевременно выявлять проблемы.

При ручном сборе отзывов возникают сложности: информация поступает через разные каналы, её необходимо систематизировать, а для анализа результатов приходится дополнительно обрабатывать данные.

Разработанный бот позволяет автоматизировать этот процесс.

Пользователь может оставить оценку по пятибалльной шкале и написать комментарий. Бот сохраняет отзыв, уведомляет администратора и формирует базовую статистику.

### 1.3. Почему я выбрал эту задачу

Я выбрал эту задачу по нескольким причинам.

Во-первых, она имеет практическое применение в бизнесе и может использоваться организациями, заинтересованными в повышении качества обслуживания.

Во-вторых, проект позволяет реализовать несколько важных функций: взаимодействие с пользователем, обработку сообщений, сохранение информации, автоматические уведомления и разграничение прав доступа.

В-третьих, разработка такого бота позволяет оценить возможности LLM как инструмента создания программных продуктов без необходимости самостоятельно писать весь код с нуля.

## 2. Промпт для LLM и процесс разработки

### 2.1. Формирование исходного промпта

На первом этапе я определил функциональные и технические требования к будущему боту.

Мне было важно, чтобы пользователь мог не просто отправить текстовое сообщение, а пройти последовательный процесс сбора обратной связи: выбрать оценку, написать комментарий и получить подтверждение.

Также я предусмотрел отдельные функции для администратора.

Для генерации кода был подготовлен следующий промпт:

> Создай Telegram-бота Feedback Assistant на Python 3.9 с использованием библиотеки python-telegram-bot.
>
> Бот предназначен для сбора обратной связи о качестве обслуживания клиентов.
>
> Функционал:
> - /start — приветствие и меню.
> - /feedback — сбор оценки от 1 до 5 и текстового комментария.
> - /stats — количество отзывов и средняя оценка.
> - /help — список команд.
> - Сохранение отзывов в JSON с датой и временем.
> - Уведомление администратора о новых отзывах.
> - Обработка некорректного ввода и ошибок.
>
> Требования:
> - Совместимость с Python 3.9.
> - Токен и ID администратора хранить в .env.
> - Использовать python-dotenv.
> - Не хранить секретные данные в коде.
> - Добавить комментарии к коду.
>
> Создай файлы bot.py, requirements.txt, README.md, .env.example и .gitignore. Предусмотри корректную обработку отсутствующих файлов и пустой статистики.

## 3. Стек технологий

Для разработки использовались следующие технологии:

| Технология | Назначение |
|---|---|
| Python 3.9 | Основной язык программирования |
| python-telegram-bot 20.8 | Взаимодействие с Telegram Bot API |
| python-dotenv 1.0.1 | Загрузка токена и ID администратора из `.env` |
| JSON | Локальное хранение отзывов |
| Telegram Bot API | Получение сообщений и отправка ответов |
| Terminal | Создание файлов, установка зависимостей и запуск |
| GitHub | Публикация проекта и отчётных материалов |
| LLM | Генерация кода и помощь в процессе разработки |

Python был выбран благодаря доступности библиотек для создания Telegram-ботов и относительной простоте синтаксиса.

Библиотека `python-telegram-bot` позволяет реализовать обработку команд и последовательных диалогов с пользователями.

`python-dotenv` используется для безопасного отделения настроек от исходного кода.

JSON был выбран как простой формат хранения данных, достаточный для небольшого учебного проекта и не требующий настройки отдельной базы данных.

## 5. Трудности и способы их решения

### 5.1. Отсутствие соединения с Telegram API

При первом запуске приложение завершилось с ошибкой:

`telegram.error.TimedOut: Timed out`

Для проверки сетевого подключения я использовал команду:

`curl -I --connect-timeout 10 https://api.telegram.org`

Первоначально соединение не устанавливалось.

Проблема была связана с нарушением интернет-соединения, а не с синтаксисом программы.

**Решение:** я переключил MacBook на мобильный интернет и повторил проверку. После этого сервер Telegram вернул HTTP-ответ, подтвердив восстановление соединения.

### 5.2. Ошибка токена

После восстановления подключения возникла ошибка:

`telegram.error.InvalidToken`

Она означала, что Telegram отклонил токен, указанный в настройках.

**Решение:** я получил актуальный токен через BotFather и обновил значение `BOT_TOKEN` в файле `.env`.

После этого приложение успешно подключилось к Telegram и начало обрабатывать команды.

### 5.3. Подготовка проекта к публикации

При размещении проекта на GitHub важно было не опубликовать токен бота и пользовательские данные.

**Решение:** я использовал `.gitignore`, исключил конфиденциальные файлы из архива и подготовил `.env.example` с примером настроек.

Для организации учебных материалов был создан репозиторий `vibe-coding-labs`, рассчитанный на три лабораторные работы.
